# 第二阶段待确认的业务场景

本清单来自已下线能力及调用方，只供下一阶段需求评审；本阶段不实现新系统，也不要求沿用 OneBot、队列、表结构、限流算法、接口或页面。

| 原调用场景 | 待确认的业务诉求 | 需要产品确认 |
| --- | --- | --- |
| 入群申请与成员变化 | 将站内身份、主人物军团和职权与群成员资格关联 | 准入条件、资料缺失处理、人工责任与权限 |
| 群成员周期核对 | 发现身份变化和不再符合资格的成员 | 检查时效、误判保护、清退是否允许自动执行 |
| 入群或核对后更新名片 | 让群内成员名称反映可识别的站内身份 | 展示内容、更新授权与用户可控性 |
| 舰队发布后的 QQ Ping | 将行动时间、指挥、重要性、PAP、说明及配装通知参与者 | 渠道、目标、发送时机、是否需要全体提醒 |
| Webhook 测试发送 | 管理员确认通知配置是否可用 | 送达反馈、失败展示与权限 |
| 建筑燃料或增强计时临近阈值 | 提醒负责人及时补给或处理防御窗口，避免重复打扰 | 接收人、阈值、提醒频率、恢复后再提醒规则 |
| 治理运营查看与故障处理 | 了解处理结果、异常原因并能纠正误操作 | 最小审计数据、保留期、失败处理责任 |

共享身份与业务数据仍以现有用户、人物、职权、舰队和建筑模块为准。新渠道选择、部署形态、多机器人、重试、幂等及监控设计均需下一阶段重新论证，不能将旧实现参数直接升级为产品要求。
