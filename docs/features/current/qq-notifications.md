# QQ 业务通知

## A：通用群通知规则与验收

默认关闭。超管且具有 `system.manage` 可在双前端 `/system/qqbot` 配置通用通知开关与最多 50 个不重复的正整数群号。测试只发送服务端固定纯文本，无任意协议或任意消息入口，有效期最多五分钟。浏览器保留测试业务键与期限，网络失败后再次点击复用同一意图；只有“新建测试意图”创建新键。

内部 `QQNotificationService.Submit` 要求渠道、稳定业务键、关联 ID、文本及绝对过期时间。文本与有效期遵循调度契约（最长七天）。同键相同内容返回原逐群操作；关联 ID、内容或期限变化报冲突。首次提交冻结目标群，配置变化不扩大发送范围。业务方传入事务，通知和全部目标操作随业务一起提交或回滚。业务键的生命周期由业务方负责，不得重用于另一事件。

业务逐群状态为 `pending / confirmed / failed / expired / unknown / cancelled`。入队只产生 pending，持久结果消费者将平台成功转换为 confirmed；unknown 不等同失败且不得重发。每群独立消费结果，重复消费不会覆盖已有终态。没有通过通用运维重试按钮生成不被业务跟踪的新操作；补偿必须由业务定义新意图。

启用渠道必须至少有一个目标。关闭渠道后，新意图拒绝，尚未执行的操作在执行前读取当前渠道并取消。停用与执行准入在单实例锁内串行；已开始的外部操作不能撤回。传输连接、限流、重试、错误分类和风控继续由统一调度负责。配置、通知和结果留作业务审计记录，目前没有自动清理策略；列表仅展示最近 200 个目标结果。

验收测试覆盖：外层事务回滚无残留；重复调用不增加操作；同键异内容拒绝；首次目标冻结；两群不同终态独立记账；重复结果幂等；关闭后拒绝新意图并使旧任务失效；过期不发送，结果经过持久消费才更新业务状态。平台成功只表示平台确认，不表示用户已读。

## 跨模块安全规则（用户已确认）

D/F：未绑定 QQ、无主人物或军团资料缺失均为资料不足，只记录并自动复查，不自动拒绝或清退。军团和职权同时配置取 AND，空规则不放行。F 清退门槛每群配置，默认连续三轮且至少二十四小时；同轮重试不增加次数。

A–G 使用新的独立业务模型；旧治理表、代码和直连 NapCat 路径均不得恢复。

## B：舰队通知规则与验收场景

创建舰队的 `send_ping` 在同一数据库事务内提交一次 `fleet:{id}:created` 通知。舰队 QQ 渠道独立开关，关闭或没有配置时跳过 QQ。有效期取“舰队创建后三十分钟”和“舰队开始时间”的较早者；已经到期则不提交，重启或重连不补发。文本包含舰队名称、FC、时间、重要性、PAP 和说明，纯文本无全体提醒；超出协议文本上限时按 UTF-8 截断。

数据库提交失败时舰队也未创建；提交后通知失败、过期或未知只影响通知结果，不修改舰队创建结果。相同舰队创建事件重复调用复用原操作。其他 Webhook 渠道继续独立，QQ 不通过 Webhook 或裸 goroutine 发送。

验收场景：舰队与通知同事务回滚；创建事件重复调用只产生一组操作；已过期不产生发送；渠道停用无发送；平台失败不能删除或撤销已创建舰队。

## C：建筑预警规则与验收场景

建筑预警独立使用 structure 渠道，默认关闭。每小时扫描本地建筑快照；仅使用一天内的新鲜快照，缺失或过旧快照不代表恢复。复用建筑设置的燃料、增强阈值，零值关闭对应预警。燃料低于阈值或增强进入阈值窗口触发一次；恢复后再进入告警为新事件，增强到期目标改变也为新事件。

每建筑每告警种类维护独立状态与递增事件版本，状态变化和通知提交同事务。有效期最长六小时，增强预警还受增强结束时刻约束。每群仍独立为 pending、confirmed、failed、expired、unknown 或 cancelled，入队绝不更新为 confirmed。

补偿边界：调度只对明确临时失败重试；永久失败、过期和未知不自动创建第二条业务意图，也不重发已确认目标。后续扫描不对同一活跃事件重复告警；恢复再告警或增强目标改变才生成下一事件。停用取消旧未执行通知，重启或重新启用不重放已经记录的活跃事件。没有新增人工补发接口。

验收场景：扫描重跑不重复入队；恢复后再告警生成新事件；增强目标变化生成新事件；状态和通知事务回滚；逐群失败独立；结果消费前保持 pending；过旧快照不解除告警；零阈值不发送。

## D：入群申请规则与验收场景

申请以群、协议 flag 和 subtype 的稳定哈希独立建模，默认记录、不自动拒绝。独立准入开关允许明确合格者自动批准；自动拒绝需另外开启，仅对明确不匹配者生效。军团与职权各自匹配任一配置值，两类同时配置取 AND；空规则、QQ 多重绑定、无主人物或军团资料缺失均不自动放行。资料不足定期复查，数据库故障由持久事件消费重试。

申请有效期二十四小时（从事件时间计算，上限为当前接收后二十四小时），到期不执行。动作发送前复查申请状态、当前规则版本和本地资格。一个申请一旦选择批准或拒绝就不自动选择相反动作；旧决策失效后保守记录，管理员在 QQ 客户端处理，无新增人工业务动作接口。

验收场景：重复事件不重复申请/动作；军团与职权 AND；空规则不批准；未开启自动拒绝不拒绝；资料不足复查；规则或资格变化使旧动作无效；同申请不能产生有效相反动作。

## E：群名片规则与验收场景

独立名片开关，默认关闭。支持 `{character_name}`、`{corporation_name}`、`{nickname}`、`{qq}`，未知变量拒绝；军团名称取本地实体名称缓存，缺失时等待资料，不用军团 ID 冒充名称。不匹配或资料不足的成员不产生名片动作。

加入事件与巡检均调用同一名片计划入口。相同目标不再创建动作；目标改变后取消旧排队动作，版本化提交新绝对值名片。每成员两次实际写入准入间隔至少一分钟，业务频率限制持久化，协议限流仍全部复用调度。停用将旧未执行操作持久取消，已开始调用无法撤回。

验收场景：相同目标幂等；目标改变取消旧动作；军团真实名称与未知名称等待；加入与巡检共用入口；关闭后重新开启不复活旧操作；同成员一分钟内不会准入两次写入。

## F：成员巡检与自动清退规则与验收场景

巡检独立开关，默认关闭；自动清退另设开关，默认仅记录。启用巡检后每十五分钟新建一轮，经统一调度读取成员列表。成功结果冻结成员快照及本地已知成员的并集，逐成员完成标记就是可恢复检查点。每轮每成员判断、状态、动作意图和完成标记同事务提交。巡检完成只表示判断完成，外部动作另看关联操作结果。

每群默认连续三轮明确不匹配且至少二十四小时观察才允许清退；门槛可配置。资料不足或不明确资格不累计，并中断连续确认链；资格恢复、重新加入或规则变更重置确认链并取消旧清退。新加入/离开事件的接收时间晚于快照请求时间时，旧快照跳过该成员，不覆盖事件。只清退明确不匹配者，发送前复核当前规则、资格、成员生命周期、确认链、轮次和观察期；切回仅记录会持久取消旧清退。

验收场景：重启继续未完成成员；同轮重试不重复确认；旧快照不标记新成员离群；资料不足不累计；恢复资格使旧动作无效；规则变化和重新入群重置确认；仅记录不执行旧清退；巡检完成不等于清退完成。

## G：管理与审计规则与验收场景

双前端 `/system/qqbot` 提供群规则配置及只读业务审计：申请、成员、巡检、逐成员判断依据和关联操作 ID。关联操作详情、连接、Redis 限流和风控沿用调度运维。所有管理路由要求 `super_admin` 和 `system.manage`，不增加手工批准、拒绝、改名片或清退接口。

配置仅接收业务字段；默认确认三轮、观察二十四小时，显式零小时可设置，确认次数必须大于零。相同规则重复保存不改变版本，不打断确认链；语义变化提高规则版本并使旧动作失效。申请协议 flag 不在申请列表响应中暴露；调度原始请求仍仅供超管运维查看。业务审计列表有上限，不自动清除业务记录。

## 已知限制

- 单实例连接与执行语义沿用统一调度；不承诺 QQ 平台无法提供的严格一次发送，未知写结果不自动重发。
- 申请二十四小时为本地有效期，不代表目标 NapCat 的 flag 保证有效；平台拒绝/未知保留审计。同申请失效决策不会自动转为相反动作，需在 QQ 客户端处理。
- 军团真实名称未进入本地实体缓存时名片等待，不在持久消费事务中调用 ESI。重新入群视为新成员生命周期，允许再次设置目标名片。
- 业务表目前不自动清理；列表有上限（规则全量、巡检最近 100、其他最近 200）。没有新增导出、分页或人工补发操作。
- 一分钟复查和十五分钟巡检为调度默认节奏，单次最多推进一百个成员检查点；大群需要多次推进。数据库异常会保留未完成检查点，暂不跳过错误成员。
- 自动化验证覆盖 SQLite、测试 Redis 和模拟 OneBot 对端；隔离 PostgreSQL/Redis 专项结果见验证指南。真实 NapCat 版本与 QQ 权限仍需部署环境验收。
