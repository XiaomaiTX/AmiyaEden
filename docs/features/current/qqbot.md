# QQ 机器人调度基础设施

提供单机器人 OneBot V11 反向 Universal WebSocket、持久操作和事件收件箱、至少一次结果/事件消费、Redis 强制限流、读写独立熔断、超管运维。默认关闭，无任何真实业务自动写操作。群治理、舰队通知和建筑预警继续下线。

双前端 `/system/qqbot` 均仅超管访问，后端还执行 `system.manage` 能力检查。页面展示连接、统一限流间隔及等待原因、读写风控、队列、尝试、事件及消费者失败；配置 Token 只写不读。人工取消不能撤回平台已接受的操作；受限重试不覆盖原终态。权限遵循 [权限架构](../../architecture/auth-and-permissions.md)，接口见 [路由索引](../../api/route-index.md)。

[PRD、状态机、数据模型及内部服务契约](../../architecture/qqbot-dispatch.md) 定义调度语义。消费者须在启动 worker 前注册，禁止通过公开接口执行任意 OneBot action。生产者必须传入稳定业务键；与业务数据库同事务提交时，只有外层事务提交成功才代表接收成功。消费者必须使用传入事务提交本地副作用，并保持幂等。

运行时每 250ms 领取一次操作；风控半开只放行一个真实操作，所有读写先经 Redis。Redis 故障、断连、限流、风控只暂停。未知发送/申请/清退结果不重试；读取和名片绝对值设置允许在有效期内恢复。永久错误不自动重试，明确临时失败最多三次，人工只允许一个重试子操作。

每小时物理清理：事件七天（未完成/死信消费关联事件保留到消费记录清理），操作终态、尝试及投递九十天。消费七天仍未完成转死信。幂等保证仅在操作记录保留窗口内有效。平台成功不表示用户已读，不承诺平台无法提供的严格一次发送。

事件持久化前无协议 ack/replay 支持，平台推送到数据库落盘之间存在不可消除的损失窗口；队列满、非法数据或数据库不可用会关闭连接并明确暴露错误，不会伪装为接收成功。入库失败保留当前事件重试。关停尝试在三秒预算内落盘内存队列，失败写日志。配置的 CIDR 对 TCP 对端校验，不信任转发头；反向连接应直连后端受限端口。
